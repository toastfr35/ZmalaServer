# Server requirement quality review — 9 November 2026

This second pass follows the [implementation review](2026-11-09.md) at Server
commit `ce2358c`. Its purpose is to make existing obligations easier to interpret
and verify, without changing runtime behavior or adding features.
Tracking: [Server #30](https://github.com/toastfr35/ZmalaServer/issues/30).

All 36 HLRs and 117 LLRs retain their IDs, parent links, scope and ownership.
The twelve LLRs below needed more precise acceptance boundaries. No imported
product item or shared peer contract changes in this pass. Version remains 0.4.11.

The changes retain cohesive lifecycle requirements and use paragraphs to separate
their independently testable clauses. HLRs remain outcome-focused. The authoring
guidance in the requirements README now asks for actors, prerequisites, units,
inclusive boundaries, observable failures and retry/concurrency semantics, while
discouraging repeated policies and incidental implementation detail.

## Verification and remaining assertion coverage

- `make requirements` passed: 36 Server HLRs, 117 LLRs, 92 mapped runtime files
  and 83 test plans, with no unmapped Server requirement. Stable metadata was
  checked against the previous revision; no review/link markers were cleared.
- The thirteen existing LLT suites relevant to these changes ran locally:
  **62 passed, zero failed, zero skipped**. Their fixtures use synthetic identities
  and do not execute real terminal commands or change real network policy.
- The expanded verification fields are acceptance plans, not claims that every
  listed boundary already has an executable assertion. Inspection found concrete
  gaps in the mapped SIP-bound, call-photo, update-cache and Wi-Fi payload suites.
  [Server #31](https://github.com/toastfr35/ZmalaServer/issues/31) records the
  missing boundary tables, global quota/decoder cases and exact-clock cases for
  a dedicated test pass. No runtime defect is inferred solely from a missing test.
- The source's 254-byte Wi-Fi encoding guard is not treated as a reachable input
  acceptance boundary: the current SSID/password limits admit at most 216 escaped
  ASCII bytes. Verification instead uses maximal valid escaped inputs and
  non-ASCII compact payloads.
- GitHub Verify must pass on the final PR commit before merge. The PR check record
  carries that execution result; local trace and fixture results do not replace
  hardware, Firebase or opt-in cross-component network qualification.
