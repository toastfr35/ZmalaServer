# Server requirements review — 9 November 2026

## Baseline and method

Reviewed Server main at `9ca27a5` (version 0.4.10), starting with both peer
contracts and `ownership.json`, then the 36 HLRs, 117 LLRs, implementation
anchors and referenced verification plans across all 16 Server themes.
The 13 imported product parents remain owned by Zmala and are unchanged.
Tracking: [Server #28](https://github.com/toastfr35/ZmalaServer/issues/28).

The baseline trace audit passed before changes: 92 runtime source files mapped,
117 LLRs anchored and 83 test plans, with no unmapped Server HLR or LLR. This
establishes trace completeness, not behavioral correctness. Reading the text
against code and tests exposed the discrepancies below despite that clean audit.

## Findings and changes

| Finding | Resolution and evidence |
| --- | --- |
| `LLR-SRV-CONFIG-017` contradicted `LLR-SRV-CONFIG-025`: it omitted 1800 seconds and still prescribed a 30-second default. | Refer to CONFIG-025 for the timeout policy. `defaults.js`, `terminal-settings.js`, `store.js` and `configuration-policy.test.js` already implement and verify the 1800-second default while preserving explicit shorter choices. |
| `LLR-SRV-AUTH-020` described only Terminal bearer identities. | Include enrolled App identities and their Terminal-route exclusions. The handler, device routes, account LLT and App enrollment HLT already enforce this distinction; extend the existing account test trace. |
| `LLR-SRV-CALL-005` described caller proof only for Terminal recipients. | Include App recipients and the existing canonical HMAC and credential-header removal. `sip-dialogs.js` supplies both; `sip-identity.test.js` already checks both recipient keys and now explicitly checks stripped caller credentials. |
| `LLR-SRV-START-005` and `LLR-SRV-PRESENCE-002` described only UDP/TCP without the secure deployment qualification. | Distinguish LAN transports from the existing TLS-only policy in MEDIA-015. `SipServer.start`, `SecureCalls.listener` and `secure-calls.test.js` establish the mode boundary. |
| The Terminal contract incorrectly listed 360p as an accepted Server profile write. | Document 480p/720p/1080p writes and migration of saved 360p to 480p, matching `terminal-settings.js`, `migrations.js`, `configuration-policy.test.js` and `video-settings.test.js`. |
| The Terminal contract claimed server-generated callback SIP notices carry Terminal message proofs. | Document the separate delivery paths. `Callbacks.deliver` excludes Terminal SIP destinations; Terminal callbacks arrive through configuration polling. `SipMessages.notifyCallback` sends legacy App notices without Terminal proof headers; App push hints use their own signed format. |
| Completed TV test results prevented backup export and validation. | Fix `validateFiles` to pass the archived account's device ID to `terminalProfileFields`. Previously its empty default made correctly bound results fail. Extend BACKUP-005 and add a regression covering export, decode, restore, wrong-device/model rejection and profiles without results. The test failed before the fix and passed afterward. |

Both Terminal contract corrections are coordinated with
[Terminal #44](https://github.com/toastfr35/ZmalaTerminal/issues/44); the two
copies contain identical text. They describe existing behavior and introduce
no wire change. The App contract required no change in this review. Stable
requirement IDs and existing review/link markers are preserved.

The backup correction changes runtime behavior, so the component version advances
to 0.4.11. This review does not publish a release or deploy to an appliance.

## Verification evidence

- `make requirements`: passed after changes; unchanged baseline counts and no
  unmapped requirements. The generated offline report is not committed.
- `make test-llt test-hlt test-adhoc` on Windows: 271 passed, 8 skipped. This
  includes 199 JavaScript LLT, 19 Python LLT, 50 JavaScript HLT, two JavaScript
  tooling tests and one Python packaging test.
- Skips: one release-data symlink LLT, two production-process HLTs, two
  HTTP portrait-conversion HLTs, two Linux firewall-namespace tests and one
  installed-Pi storage test. A skipped test is not acceptance evidence.
- Type checks, generated-admin consistency, Python lint, changed-JavaScript
  formatting, whitespace checks, version progression and a local package build
  passed. GitHub Verify is the required Linux gate on the final PR commit;
  its result belongs to the PR check record.
- The matching Terminal documentation change passed its local requirements
  audit. Its own Verify workflow remains required before merge.

Physical Pi reboot/storage/SSH behavior, real Firebase delivery, camera/TV/USB
behavior and the opt-in cross-component LAN/NAT and TLS network labs were not
executed in this review. Their existing plans remain required for the relevant
hardware or deployment acceptance; fixture checks do not replace them.
